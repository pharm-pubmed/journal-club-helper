# Journal Club Helper: Critical Appraisal for PubMed

A Chrome extension (Manifest V3) that adds a structured critical-appraisal workflow to PubMed abstract pages: study design detection, PICO, ARR / RRR / NNT with 95% CI, design-specific validity checklists, and a one-page journal club summary.

It does **not** summarize papers. It provides the appraisal template and fills it in with you.

## Status

Pre-alpha. Publish and validate the free MVP before investing in paid features. Existing GitHub milestone labels are v0.1 MVP, v0.2 Paid features, v0.3 Public release and v1.0; the planned execution order is MVP → free public release → paid validation. Issue and milestone updates are still pending.

The monetization plan in [the product spec](docs/SPEC.ja.md) tests presentation-ready exports as the paid value, with optional AI assistance. The initial $39/year price is an unvalidated hypothesis. Paid exports and billing are not implemented.

## Positioning

- For medical residents, pharmacy residents (PGY1/2), medical students, and nurse practitioners preparing journal club.
- Educational and appraisal aid only. Not a clinical decision-support tool. No recommendations are generated.
- No servers, no accounts, no analytics. Everything runs locally in the browser. AI features (v0.2) call the provider directly with the user's own API key.
- Not affiliated with NLM / NIH. PubMed is a registered trademark of the U.S. National Library of Medicine.

## Development

Requires Node 22 and pnpm 9 (`corepack enable` gives you the pinned version).

```bash
pnpm install       # also runs `wxt prepare` to generate .wxt/tsconfig.json
pnpm dev           # WXT dev server with HMR
pnpm build         # production build into .output/chrome-mv3
pnpm zip           # store-ready zip
pnpm test          # Vitest, unit tests for src/lib
pnpm test:e2e      # Playwright: the built extension in Chromium, on saved PubMed pages
pnpm lint          # ESLint
pnpm typecheck     # wxt prepare && tsc --noEmit
pnpm check:manifest  # fails if the built manifest's permissions drift from the spec
```

Load the unpacked extension from `.output/chrome-mv3`.

Stack: WXT, TypeScript (strict), Preact, Vitest, Playwright, pnpm.

### Layout

| Path                   | What lives there                                                                 |
| ---------------------- | -------------------------------------------------------------------------------- |
| `src/lib/`             | Pure logic. No DOM, no `chrome.*`, unit-tested. This is where the product lives. |
| `src/entrypoints/`     | Content script, background worker, side panel, options page.                     |
| `src/ui/`              | Preact components for the side panel and the options page.                       |
| `src/data/checklists/` | The validity checklists as JSON, so wording changes need no code change.         |
| `tests/`               | Vitest specs and HTML fixtures of real PubMed pages.                             |

### Two conventions worth knowing

**All cross-module types live in `src/lib/types.ts`.** The module that owns the behaviour re-exports the types it owns, so `import type { DesignClassification } from './design-classifier'` and `from './types'` are the same type. This keeps the lib modules independent of each other.

**The permission set is frozen.** `scripts/check-manifest.mjs` runs in CI and fails the build if the manifest's permission arrays change at all. Widening them is a product decision, not a refactor.

## Permissions

Two: `storage` and `sidePanel`, plus a host permission for `pubmed.ncbi.nlm.nih.gov` and nothing else. One optional host permission for NCBI E-utilities, requested only when a page cannot be read and you ask the panel to fetch the record from NCBI instead. No `tabs`, no `<all_urls>`, no `scripting`.

Declared permissions track what the code can actually do, not the roadmap: the AI provider hosts arrive with the AI features in v0.2. [CHROMEWEBSTORE.md](CHROMEWEBSTORE.md) carries the per-permission justification for store review.

`activeTab` was in the spec and has been removed: `chrome.tabs.query` needs no permission at all, and `chrome.tabs.sendMessage` is already covered by the PubMed host permission, so it granted nothing the extension used.
